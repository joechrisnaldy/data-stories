The percent-unit rule of the blog gate, 2026-11-17. Branch gate/pct-unit from main at cca6fbe. Run with Python 3.13.14.

The defect on record. On 2026-11-17 Post 31 (outlook-outage) rendered "In GWI's survey, 76.4 of internet users ...",
"against 54.9 for WhatsApp", "In Indonesia the picture flips: 92.7 of internet users ..." and, in chart 2's alt text,
"email 76.4 and WhatsApp 54.9 in GWI's surveyed markets, WhatsApp 92.7 in Indonesia". pct0 and pct1 print a bare number
(gate/formats.py), and the full gate printed GATE PASSED. The word "percent" was added by hand the same day.

The invariant is stated in gate/README.md (the numbers row of What it checks); its limits and known false positives
are listed there too.

How it was tested (gate/README.md, Changing the gate):
- Tests first: the new self-tests in gate/tests/test_numbers_pairs.py (PercentUnitTest) and gate/tests/test_text_config.py,
  each seen failing before the code it tests or under a deliberately wrong version of it. The self-test runs 363 tests
  here (339 on main).
- A replay on every post with a gate.toml, gate/replay/replay_units.py; its part 3 is an oracle written apart from the
  rule's splitter.
- The real defect replayed: a copy of Post 31 with its pre-fix words restored, re-rendered, and its mdx line removed, so
  the published check is SKIPPED in both runs of section 1.
- ONE attack round: five attackers (false negatives, false positives, crashes, splitter and coverage, harness and
  evidence), each finding re-run by an independent skeptic, 31 findings. Fixed: every layout in which the defect on record
  passed in the markdown the posts use (list items, a stop before a closing mark, table rows, whose column header may name
  the unit, sentence openers, heading, image and quote lines, 'devs.', the ellipsis, code and HTML comments) and the
  replay's mutants, which had been cut by the splitter under test. The rest is documented in gate/README.md.
- ONE verification round: five verifiers re-ran every attack reproducer on the fixed code, and a sixth replayed every
  recorded attack of the 2026-10-09 audit on Post 25 (gate/replay/replay_audit.py): no outcome differs from main's record
  in audit/gate-replay-2026-11-17.txt. It upheld further shapes of the defect. Fixed after it, each with a test: a line
  ending in a hard break, a sentence opening with anything but a lowercase letter, an escaped pipe in a table cell; and
  three replay faults (part 2 honours a column header's unit; the oracle reads the ellipsis and 'devs.' as the rule does; a
  miss counts as a known limit only when every boundary inside the rule's sentence opens lowercase). These last fixes had
  no round of their own; the verification round's corpus of injected cases was re-run on them (section 4). Everything
  else it upheld is documented in gate/README.md.
- A security review before the commit found nothing above LOW. Two of the new regular expressions were quadratic on
  adversarial text (a line holding tens of thousands of spaces; thousands of unclosed '<!--' openers). Both are bounded
  now: a run of spaces starts once, and an unclosed comment or code fence is masked to the end of the text, as Markdown
  reads it. The timings before and after are section 5.
